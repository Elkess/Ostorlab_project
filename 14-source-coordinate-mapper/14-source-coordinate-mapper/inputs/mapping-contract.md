# MapleLens mapping contract

- C1: Input is an object with arrays `segments` and `findings`. Every segment is an object with nonblank strings `segment_id`, `generated_file`, `original_file` and positive integer `generated_start`, `generated_end`, `original_start`. Booleans are not integers. Require start <= end and unique segment IDs. Any invalid segment or top-level schema fails the whole input (exit 2), even if no finding uses it. Extra fields are ignored.
- C2: Paths are opaque, exact strings. Do not trim, normalize case, resolve paths, or replace separators. Nonblank means a string containing a non-whitespace character; preserve its original bytes. No source files are needed.
- C3: A valid finding has nonblank strings `finding_id`, `generated_file` and a positive integer `generated_line` (not bool). Invalid finding rows produce one `rejected` diagnostic with one-based `row`, `finding_id` if it is a nonblank string (otherwise null), and readable `reason`. Continue processing. IDs are preserved, never deduplicated.
- C4: A segment matches only the exact generated path and inclusive range [generated_start, generated_end]. No matches means `unmapped`; multiple matches means `ambiguous`, even when targets coincide. Exactly one means `mapped`, with original line = original_start + generated_line - generated_start. Never extrapolate across gaps.
- C5: Output `results` for valid findings in input order: `row`, `finding_id`, `generated_file`, `generated_line`, `status`, `matches` (sorted segment IDs), `target` ({`file`, `line`} only for mapped; otherwise null). Output `rejected` in input order and `summary`: `input_rows`, `mapped`, `unmapped`, `ambiguous`, `rejected_rows`. These four classifications partition input rows. Success exits 0 even with rejected rows; empty arrays are valid. Repeated runs are identical and input is immutable.
